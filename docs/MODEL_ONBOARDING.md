# 模型配置手册

本文说明当前 Prism 运维台的模型配置流程。配置直接写入活动目录，保存成功后由下一次请求读取；不需要配置历史、草稿、发布、证明、激活或部署代次。

## 1. 配置边界

运维人员维护五类信息：

| 对象 | 内容 |
|---|---|
| 模型 | 对外模型名、显示名、类型和可见性 |
| 服务规格 | 操作、服务等级、变体和下游入口 |
| 上游 | 渠道、上游模型名、请求端点和 Adapter |
| 映射 | 参数约束及上下游 JSON 字段映射 |
| 商业配置 | 用户售价、上游成本、路由优先级、权重和 API Key |

一次请求开始时读取一份完整配置，执行期间不再重新读取。编辑只影响保存成功后开始的新请求。

## 2. 准备信息

配置前确认：

- 上游 API 文档，包括鉴权、请求路径、请求字段、响应字段和异步查询方式；
- 对外模型名与上游真实模型名；
- 模型类型：LLM、图片或视频；
- 上游渠道、Base URL 和 API Key；
- 用户售价、上游成本及计费单位；
- 下游需要开放的 Prism API 路径。

不要把价格或 API Key 写入映射 JSON。价格由费率配置管理，Key 由凭据池管理。

## 3. 直接配置流程

1. 打开“运维台 > 上游网关”，按 LLM、图片或视频筛选网关。
2. 打开网关详情，在“API Key”中建立 Key 池并添加 Key。
3. 进入“模型与映射”，点击“接入模型”。
4. 选择 Key 池、接入格式和对外模型，填写上游模型名、地址、路径及 JSON 映射。
5. 保存后在同一页核对“上游模型 → 对外模型”关系；需要更改时点击该上游模型的编辑按钮。
6. 进入“模型”视图设置用户售价、上游成本、下游入口和线路优先级。售价和成本必须明确填写；系统不会把缺失成本当成零。
7. 发起一笔真实的最小请求，在“调用记录”中检查路由、上游响应和计费结果。

页面会携带当前 `config_version` 防止并发覆盖。若提示配置已更新，刷新详情后重新提交；不要绕过版本检查。

“接入模型”对新模型使用一次性原子写入：同时创建对外模型、服务规格、上游 Transport、Key 池关系、路由和两侧费率。保存失败时整笔回滚，成功后只增加一次 `config_version`。接口为 `POST /api/admin/unified-gateway/catalog-changes/model-onboard`；请求中的 `sell_rate.unit_price` 和 `cost_rate.unit_price` 使用当前结算币种记录，运维人员不需要先建立价格证据或走发布流程。

## 4. 按模型类型配置

### LLM

根据上游协议选择 Adapter，例如 OpenAI Chat、OpenAI Responses、Anthropic Messages 或 Google Generate Content。重点核对：

- 下游入口与操作类型匹配；
- 上游模型名正确；
- 流式与非流式响应都符合所选 Adapter；
- Token 计费单位分别对应输入与输出。

### 图片

核对生成或编辑入口、图片尺寸、张数、质量等参数约束。价格与成本按实际计费单位配置，不写入映射 JSON。

### 视频

视频的 JSON 指上下游关系映射，不代表视频只能使用某种固定请求格式。映射应明确：

- 创建任务时各字段从下游 JSON 写到上游 JSON 的位置；
- 上游任务 ID、状态、进度、结果 URL 和错误字段的读取位置；
- 轮询路径、间隔和终态；
- 上游支持回调时的回调字段与认证方式；
- 分辨率、时长、比例等参数约束。

使用固定 Adapter 时只配置其开放字段；使用 Generic Video 时按 Adapter Manifest 填写完整映射。不要凭经验猜字段路径。

## 5. API Key

新建和替换的上游 API Key 明文保存在 `gw_credentials.secret`。这是当前接受的存储方案。

- 写入接口接收完整 Key；
- 读取接口不返回 Key，也不生成可还原的展示值；
- 调用日志和审计记录不保存 Key 内容；
- 替换或停用后无需发布，下一次请求使用新状态；
- 旧加密凭据仍可在迁移期间读取，替换后改用明文列。

`PRISM_GATEWAY_PAYLOAD_KEK_B64` 与 `PRISM_GATEWAY_PAYLOAD_HMAC_B64` 始终用于请求、结果和回调资料。只有数据库仍包含需要读取的旧加密凭据时，才需要保留 `PRISM_GATEWAY_KEK_B64` 与 `PRISM_GATEWAY_HMAC_B64`。

## 6. 保存与验证

每次保存应满足：

1. 数据库事务成功；
2. `config_version` 增加；
3. 审计记录包含操作者、对象和修改字段，但不包含 Key；
4. 下一次新请求读取修改后的配置；
5. 已开始的请求继续使用开始时固定的配置。

最小验收至少覆盖：

- LLM：一次非流式请求；
- 图片：一次生成或编辑请求；
- 视频：一次创建及轮询到终态；
- Key：替换后新请求成功，停用后不再被选择；
- 计费：售价、成本和调用记录一致。

## 7. 故障定位

| 现象 | 首先检查 |
|---|---|
| 模型不可用 | 下游入口、可见性、Offering 运行状态 |
| 没有可用上游 | 路由、凭据池、Key 状态、并发限制 |
| 上游返回参数错误 | Adapter、上游模型名、映射 JSON |
| 视频一直处理中 | 任务 ID 映射、轮询路径、状态与终态映射 |
| 金额不正确 | 售价、成本、计费单位及表达式 |
| 保存冲突 | 刷新详情，使用新的 `config_version` 重试 |

调用问题以“调用记录”中的 Call、Attempt 和上游请求日志为准；配置修改以审计记录为准。
